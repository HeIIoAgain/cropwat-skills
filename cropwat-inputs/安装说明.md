# cropwat-inputs — 生成 CROPWAT 8.0 的输入文件

从原始气象数据算出 FAO-56 参考蒸散量 ETo，生成 / 校验 CROPWAT 的四种输入文件，
并**按目录分类**搭出一个可直接运行的完整工作目录。

**这个文件夹本身就是一个完整的 DSH 技能。**

---

## 安装到 DSH

把**本文件夹整个**复制到 DSH 的技能目录，文件夹名保持 `cropwat-inputs`：

```powershell
# 默认位置（$DSH_HOME 未设置时）
Copy-Item -Recurse -Force ".\cropwat-inputs" "$env:USERPROFILE\.dsh\skills\cropwat-inputs"

# 若设了 DSH_HOME
Copy-Item -Recurse -Force ".\cropwat-inputs" "$env:DSH_HOME\skills\cropwat-inputs"
```

**只对某个项目生效**：放到项目根的 `.dsh\skills\cropwat-inputs\`。

DSH 会热加载技能，通常无需重启；新会话里看不到就重启一次。

## 完整流程：从原始气象数据到可运行的工作目录

### 第一步：准备一份气象数据 CSV

每行 = 一个地点一个月的记录，列名如下：

```
name, lat, lon, alt, year, month, tmin, tmax, rh, wind_kmd, sun_h[, rain_mm]
```

| 列 | 含义 | 单位 | 注意 |
|---|---|---|---|
| `name` | 站点/地点名 | — | 会用作文件名和文件夹名 |
| `lat` `lon` | 纬度 经度 | 度 | 北纬为正 |
| `alt` | 海拔 | m | 影响气压和辐射 |
| `tmin` `tmax` | **月平均值**最高/最低气温 | ℃ | ⚠ 不是月极值！用极值会让 ETo 虚高约 19% |
| `rh` | 月平均相对湿度 | % | |
| `wind_kmd` | 2 m 高度风速 | **km/day** | 10 m 风速要乘 0.748；m/s 要乘 86.4 |
| `sun_h` | 日照时数 | **小时/天** | ⚠ 若是"小时/月"，加 `--sun-is-monthly` 自动换算 |
| `rain_mm` | 月降水量 | mm | 缺测留空 |

### 第二步：一条龙建目录

**不用指定路径** —— 三个命令默认都输出到桌面 `CROPWRT工作文件\`：

```powershell
# ① 气候 + 降水（按地点分文件夹）
python cropwat_inputs.py build --csv weather.csv --pem --crm

# ② 作物 + 土壤（从 CROPWAT 安装目录拷 FAO 原始文件）
python cropwat_inputs.py crops --names WHEAT MAIZE RICE --soils

# ③ 稻田土壤（把缺测的水稻参数填上固定值）
python cropwat_inputs.py soil --template MEDIUM
```

每条命令开头会打印落脚点：

```
[默认] 未指定 --workdir，输出到桌面: <你的桌面>\CROPWRT工作文件
```

生成的结构：

```
<桌面>\CROPWRT工作文件\
├── Climate\<地点>\<地点>_<年份>.PEM      每个地点一个文件夹，年份都在里面
├── Rain\<地点>\<地点>_<年份>.CRM
├── Crop\<作物>.CRO
└── Soil\<土壤>.SOI                        含 Recommed-<模板>.SOI
```

想放别处就加 `--workdir "<路径>"` 覆盖。

### 经纬度不用自己填 —— 自动查

`lat` / `lon` / `alt` 都是**公开信息**。源 CSV 里没有这三列也能跑，加 `--geocode` 就行：

```powershell
python cropwat_inputs.py build --csv weather.csv --pem --crm --geocode
```

程序会：

  1. 用 **OpenStreetMap Nominatim** 查经纬度
     （中国地级行政区它覆盖好；Open-Meteo 查不到乌海/通辽/兴安盟/锡林郭勒）
  2. 查不到就用 **Open-Meteo** 兜底
  3. 用 **Open-Meteo 海拔接口**补海拔（Nominatim 不给海拔，而 `.PEM` 需要它算气压项）

**不需要任何密钥。** 结果缓存在 `~/.cropwat_geocode.json`，重跑不再联网。

同时会在源数据旁边生成一张 **站点坐标表 CSV**，务必过一眼：

```powershell
python cropwat_inputs.py geocode --csv weather.csv        # 只查，生成坐标表
python cropwat_inputs.py build --csv weather.csv --sites 站点坐标.csv   # 用你改过的坐标
```

**两点要注意**：

  1. **重名**：包头在内蒙古，也在海南；阿拉善新疆也有。
     源 CSV 里加一列 `province`（如"内蒙古"），程序会优先选那个省的结果。
  2. **查回来的是行政中心点，不是你那个气象站的点。**
     如果你的气象数据来自某个具体站点，请把坐标表里的 lat/lon/alt 改成站点的，再用 `--sites` 读回。
     **海拔尤其重要**，它直接影响 ETo 里的气压项。

### 站名必须是拉丁字符（程序会自动转换）

`.PEM` / `.CRM` 只能写 `latin-1`，**中文站名写不进去**（会直接报错）。
程序遇到中文站名会自动转成 ASCII：

```
呼和浩特  → Hohhot_City        乌兰察布 → Ulanqab_City
兴安盟    → Hinggan_League     锡林郭勒 → Xilinhot_City
阿拉善    → Alxa_League        巴彦淖尔 → Bayannur_City
```

想用自己的名字，在源 CSV 里加一列 `name_en` 指定。

### 第三步：体检

```powershell
python cropwat_inputs.py inspect "<桌面>\CROPWRT工作文件\Climate\<地点>\<地点>_<年份>.PEM"
```

会打印 12 个月的五个输入列、Rad、ETo、年 ETo，并做**自洽校验**（用前五列重算 Rad/ETo 与文件里的值对比）。

### 数据明细备查表（自动生成）

跑 `build` 时会**顺手生成一张明细表放桌面**，记录生成输入文件用到的每一个数，便于事后备查：

```
<你的桌面>\CROPWAT输入数据明细.xlsx
```

六个工作表：

| 工作表 | 内容 |
|---|---|
| **逐月明细(全部要素)** | 一行一个 地方×年×月：五个输入列 + 太阳辐射 + ETo + 降水量 |
| **年度汇总(地方×年)** | 年均气温/湿度/风速、年日照时数、年 ETo、年降水量、生长季(4-9月)降水 |
| **降水量矩阵(地方×年月)** | 地方为行、`年-月` 为列，一眼看全年分布 |
| **气温矩阵Tmax(地方×年月)** | 同上，最高气温 |
| **气温矩阵Tmin(地方×年月)** | 同上，最低气温 |
| **站点与文件** | 坐标、海拔、对应的 `.PEM` / `.CRM` 路径模板 |

不想每次生成就加 `--no-detail`；想单独重出（不重建 `.PEM`/`.CRM`）：

```powershell
python cropwat_inputs.py detail --csv weather.csv
python cropwat_inputs.py detail --csv weather.csv --out "D:\别处\明细.xlsx"
```

## 七个子命令

| 命令 | 作用 |
|---|---|
| `inspect` | 读回 `.PEM`/`.CRM` 并做自洽校验 |
| `eto` | 单点试算 FAO-56 ETo |
| `geocode` | **查地名 → 经纬度/海拔（公开信息，不用手填）** |
| `detail` | 生成数据明细备查表（不写 `.PEM`/`.CRM`） |
| `build` | 从 CSV 批量生成 `.PEM`/`.CRM`，按目录分类 |
| `crops` | 从 CROPWAT **安装根目录**复制 FAO 作物/土壤文件 |
| `soil` | 生成稻田土壤，只填模板里缺测的字段 |

```powershell
# 看作物/土壤安装目录里有什么
python cropwat_inputs.py crops --list

# 看水稻土壤参数的推荐值及依据
python cropwat_inputs.py soil --show-defaults

# 单点算 ETo（注意 --wind 单位是 m/s）
python cropwat_inputs.py eto --tmax 26.8 --tmin 14.7 --rh 67.9 `
                            --wind 2.09 --sun 7.7 --doy 196 --lat 40.81 --alt 1051
```

## 水稻的额外参数

CROPWAT 的土壤窗体有一块 **`AdditionalRiceBox`**（水稻附加区），比旱作多这些：

| 参数 | 推荐固定值 | 依据 |
|---|---|---|
| **泡田后最大渗漏率** | **5 mm/day** | 《灌溉排水设计规范》3.2.5：水稻田适宜日渗漏量 **2～8 mm/d**（粘性土取小、砂性土取大）；FAO 自带样本也是 5 |
| **最大田面水深** | **120 mm** | 节水灌溉实例的泡田定额；FAO 样本同为 120 |
| 可排水孔隙度 (SAT−FC) | 0.6 | FAO 样本值 |
| 水型标志 | 1 | FAO 样本值 |

按土壤调渗漏率：**重黏土（有犁底层）2～3 ｜ 黏壤土 5 ｜ 砂性土 6～8**；充分泡田、基本不透水的田块可填 **0**。

`soil` 命令**只填模板里缺测的字段**，模板本来有效的值不动：

```
模板 MEDIUM:  孔隙=0.4(保留)  渗漏=-999→5(补缺)  水深=-999→120(补缺)
```

**FAO 只发行 7 个 `.SOI`，只有 `BLACK CLAY SOIL` 把水稻参数填了**，其余 6 个这两个槽位全是 `-999`，所以做水稻必须用本命令生成。

作物侧也有一块水稻专属参数（**秧田期 · 整地期 · 泡田期 · 插秧日期 · 泡田水深**），
`RICE.CRO` 是 12 行（旱作 8 行）。做需水量测算时直接拷 FAO 的 `RICE.CRO` 即可。

## 最容易踩的三个坑

| 坑 | 后果 |
|---|---|
| **`.PEM` 是 Tmin 在前**（CLIMWAT 的 `.pen` 是 Tmax 在前） | 写反不报错，结果全错 |
| **FAO-56 公式里的 u2 是 m/s，而文件列是 km/day** | 直接把列值喂进公式，ETo 虚高最多 6 mm/day |
| **日照列是"小时/天"** | 写成"小时/月"会让辐射虚高约 8 倍 |

另外三个字段有坑：Rad 和 ETo 两列 **CROPWAT 会自己重算**（只有前五列是真实输入）；
`.SOI` 第 3 行是 **Delphi 风格科学计数法**（`200` → `" 2.0E+0002"`，指数 4 位）。

`SKILL.md` 里有完整的 12 条坑位清单和验证方法。
